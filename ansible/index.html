The commands you reach for at 2 a.m., and the tricks that keep you from needing them.

Everything below targets ansible-core 2.15+ with fully-qualified module names. Type / to filter; every block has a copy button.

PLAY RECAP *********************************************************************
web1   : ok=14  changed=3  unreachable=0  failed=0  skipped=2  rescued=0  ignored=0
db1    : ok=9   changed=0  unreachable=0  failed=1  skipped=0  rescued=1  ignored=0
  • ok — ran, nothing to change
  • changed — state was modified
  • failed — task errored and stopped the host
  • unreachable — SSH / connection never worked
  • skipped — when was false
  • rescued — a rescue: block caught it

01 · Inventory & reach

Can I see my hosts, and can I talk to them?

ansible all -m ping

Confirms SSH login and a working Python on every host. Not ICMP.

Tip: -o gives one line per host, easier to scan across fleets.

ansible all -i inventory/prod.ini -m ping -u deploy -k -K

Explicit inventory, remote user, prompt for SSH password (-k) and sudo password (-K).

ansible-inventory --graph
ansible-inventory --list -y
ansible-inventory --host web1

Tree view of groups, full merged inventory as YAML, or every variable that applies to one host.

Tip: --graph --vars prints variables in the tree, which is the fastest way to see where a value comes from.

ansible 'web*:&prod:!canary' --list-hosts

Dry-run a host pattern before using it in --limit. Nothing runs.

all / *every hostweb:dbunion of two groups
web:&prodin both web and prodweb:!stagingweb, excluding staging
web[0]first host in groupweb[0:2]first three hosts (slice is inclusive)
web[-1]last host in group~web\d+\.euregex, leading ~
--limit @hosts.txthosts listed in a file, one per line10.0.1.*IP glob works too
ansible all -m ansible.builtin.setup -a 'filter=ansible_distribution*'

Gather facts with a glob filter. Drop the filter for the full dump (large).

Tip: -a 'gather_subset=network' or 'gather_subset=!all,!min,hardware' limits what is collected.

ansible all -m setup --tree /tmp/facts

Write one JSON fact file per host. Grep the directory instead of re-gathering.

ansible-inventory -i aws_ec2.yml --graph
ansible-inventory -i inventory/ --list --yaml --output merged.yml

Dynamic inventory plugins (AWS, GCP, Azure, Proxmox, …) take a YAML file ending in the plugin name. Pass a directory to merge everything inside it.

ansible all -m ping -e 'ansible_python_interpreter=/usr/bin/python3'

Fixes "module failure: /usr/bin/python: not found" on hosts with only python3. Set interpreter_python = auto_silent in ansible.cfg to stop the warning for good.

02 · Ad-hoc commands

One module, many hosts, no playbook.

ansible web -a 'uptime'
ansible web -m shell -a 'ss -tlnp | grep :443'

No -m means command: no shell, so no pipes, globs or redirects. Use shell when you need them.

ansible all -b -m apt -a 'name=nginx state=present update_cache=yes'
ansible all -b -m dnf -a 'name=* state=latest'

-b is --become (sudo). Module args are key=value pairs.

Tip: -m package picks apt/dnf/etc. automatically per host.

ansible all -b -m service -a 'name=nginx state=restarted'
ansible all -b -m systemd -a 'name=nginx enabled=yes daemon_reload=yes'

Restart, enable, reload units across the fleet.

ansible all -b -m copy -a 'src=./motd dest=/etc/motd mode=0644 backup=yes'

Push one file everywhere. backup=yes keeps a timestamped copy of the old one.

Tip: -a 'content="hello\n" dest=/tmp/x' writes inline content with no source file.

ansible all -m fetch -a 'src=/var/log/nginx/error.log dest=logs/'

Pull a file from every host into logs/<hostname>/var/log/nginx/error.log. Add flat=yes to skip the path nesting.

ansible all -b -m user -a 'name=deploy groups=sudo append=yes shell=/bin/bash'
ansible all -b -m authorized_key -a "user=deploy key='{{ lookup('file', '~/.ssh/id_ed25519.pub') }}'"

Bootstrap a user and drop your key in one go.

ansible all -b -m reboot -a 'reboot_timeout=600'

Reboots and waits for SSH to come back. Far more reliable than shell: reboot.

ansible all -m debug -a 'var=hostvars[inventory_hostname]'
ansible all -m debug -a 'msg={{ ansible_host }}:{{ ansible_port | default(22) }}'

Print any variable as each host sees it, no playbook required.

ansible all -a 'df -h /' -f 50 --one-line

-f raises parallel forks (default 5). --one-line makes output grep-able.

ansible localhost -m debug -a "msg={{ lookup('env', 'HOME') }}"
ansible localhost -m debug -a "msg={{ '10.0.0.0/24' | ansible.utils.ipaddr('net') }}"

Use localhost as a Jinja scratchpad to test filters and lookups before putting them in a template.

ansible-console web -b

Interactive REPL: type apt name=htop or shell uptime against the chosen pattern with tab completion. cd db switches hosts, forks 20 tweaks parallelism.

03 · Running playbooks

The flags that matter on the ansible-playbook line.

ansible-playbook site.yml --check --diff

Dry run and show what would change, file diffs included. The single most valuable flag pair in Ansible.

Tip: tasks with check_mode: false still run for real in --check; use that for read-only commands whose output later tasks need.

ansible-playbook site.yml -l 'web*:&prod'
ansible-playbook site.yml -l web1,web2
ansible-playbook site.yml -l @failed_hosts.txt

--limit narrows the play's hosts. Always pair it with --list-hosts first when the pattern is clever.

ansible-playbook site.yml --list-tasks
ansible-playbook site.yml --list-tags
ansible-playbook site.yml --list-hosts

Inspect without executing. --list-tasks also prints each task's tags.

ansible-playbook site.yml -t deploy,restart
ansible-playbook site.yml --skip-tags slow,packages

Run or skip by tag. tags: always tasks run regardless, tags: never only run when asked explicitly.

ansible-playbook site.yml --start-at-task 'Restart nginx'

Resume a long run at the task name. Facts and registered variables from earlier tasks will be missing, so it works best with idempotent plays.

ansible-playbook site.yml --step

Prompt before every task: y run, n skip, c continue without asking. Great for the first run on prod.

ansible-playbook site.yml -e 'version=1.4.2 force=true'
ansible-playbook site.yml -e @vars/prod.yml
ansible-playbook site.yml -e '{"pkgs": ["git", "jq"]}'

--extra-vars beats every other variable source. Use @file for YAML/JSON, or inline JSON for lists and dicts.

ansible-playbook site.yml -u deploy -b --become-user=postgres -K

SSH as one user, escalate to another. -K asks for the sudo password once.

ansible-playbook site.yml --syntax-check

YAML and play structure only; it will not catch bad module args. Put it in CI next to ansible-lint.

ansible-playbook site.yml --flush-cache

Discard cached facts so gathering = smart re-collects them. The fix for "but I changed the hostname yesterday".

ansible-playbook site.yml --force-handlers

Run notified handlers even when a later task fails. Without it, a failure in the middle means your restart never happens.

ANSIBLE_CALLBACK_RESULT_FORMAT=yaml ansible-playbook site.yml
ANSIBLE_CALLBACKS_ENABLED=timer,profile_tasks ansible-playbook site.yml

YAML-formatted task results are far more readable than the JSON default. profile_tasks prints the slowest tasks at the end.

ansible-playbook site.yml -i localhost, -c local

Run a playbook against the machine you're on. The trailing comma makes the argument an inline host list instead of a file name.

ansible-pull -U https://github.com/org/infra.git -C main -i localhost, local.yml

Inverts the model: each node clones the repo and applies itself. Pair with a cron entry or systemd timer for cheap continuous config.

ansible-playbook site.yml 2>&1 | tee "runs/$(date +%F_%H%M).log"

Keep a record of every prod run. Set log_path in ansible.cfg for the same thing without remembering to do it.

04 · Debugging

When the recap is red.

ansible-playbook site.yml -v      # show task results
ansible-playbook site.yml -vvv    # + SSH commands, module args
ansible-playbook site.yml -vvvv   # + connection-plugin debug

Start at -v; jump to -vvv for "why is it connecting like that". -vvvv is for SSH and become problems.

- name: Read the service status
  ansible.builtin.command: systemctl is-active nginx
  register: nginx_state
  changed_when: false
  failed_when: nginx_state.rc not in [0, 3]

- ansible.builtin.debug:
    var: nginx_state
    verbosity: 1          # only prints with -v or higher

The canonical debug loop: register the result, decide what "failed" and "changed" mean yourself, print it at a verbosity level so it stays quiet in normal runs.

ANSIBLE_KEEP_REMOTE_FILES=1 ansible-playbook site.yml -vvv -l web1

Leaves the generated module scripts in ~/.ansible/tmp/ on the host. Run them by hand with python3 AnsiballZ_*.py explode then execute to see the real traceback.

- hosts: web
  strategy: ansible.builtin.debug   # or: debugger: on_failed  (per play/task)
  tasks:
    - ansible.builtin.template:
        src: app.conf.j2
        dest: /etc/app.conf

Drops into an interactive debugger on failure. Inside it: p task.args, p result._result, p host, task.args['dest'] = '/tmp/x', redo, continue, quit.

ansible web1 -m ansible.builtin.setup -a 'filter=ansible_default_ipv4'
ansible-inventory --host web1 | jq .ansible_host

Two ways to answer "what does Ansible think this host is".

ansible-playbook site.yml -l web1 -t debugme

Tag a diagnostic task [never, debugme]. It is invisible in normal runs and appears only when you ask.

- ansible.builtin.assert:
    that:
      - ansible_facts['distribution'] == 'Ubuntu'
      - ansible_facts['distribution_major_version'] | int >= 22
      - db_password is defined
    fail_msg: "This role needs Ubuntu 22.04+ and db_password"
    quiet: true

Fail early with a message you wrote, not a Jinja traceback three roles later.

ANSIBLE_DEBUG=1 ansible-playbook site.yml 2>debug.log

Internal engine logging: variable precedence, plugin loading, inventory parsing. Enormous output. Last resort.

ansible all -m ping -vvv 2>&1 | grep -E 'ESTABLISH|ssh -'

Shows the exact SSH command line Ansible builds, including key, user, port and ssh_args. Copy-paste it to reproduce the connection problem outside Ansible.

ansible-playbook site.yml -e 'ansible_ssh_common_args="-o ProxyJump=bastion.example.com"'

Reach hosts through a jump box for one run. Put it in group_vars to make it permanent.

05 · Vault

Secrets in git without the guilt.

ansible-vault create group_vars/prod/vault.yml
ansible-vault edit   group_vars/prod/vault.yml
ansible-vault view   group_vars/prod/vault.yml

Create, edit (in $EDITOR) or print an encrypted file. Keep vaulted vars in a separate vault.yml so git grep still finds the names.

ansible-vault encrypt secrets.yml certs/*.key
ansible-vault decrypt secrets.yml
ansible-vault rekey   secrets.yml

Encrypt existing files in place, decrypt for good, or change the password.

ansible-vault encrypt_string --vault-id prod@prompt --name 'db_password' 'S3cr3t!'

Emits a !vault | block you paste straight into a plain YAML file. Only that value is encrypted; the rest of the file stays diffable.

Tip: echo -n 'S3cr3t!' | ansible-vault encrypt_string --stdin-name db_password keeps the secret out of shell history.

ansible-playbook site.yml --ask-vault-pass
ansible-playbook site.yml --vault-password-file ~/.vault_pass.txt
ansible-playbook site.yml --vault-id prod@~/.vault_prod --vault-id dev@prompt

Supply one or many vault passwords. vault_password_file in ansible.cfg removes the flag entirely.

Tip: if the password file is executable, Ansible runs it and reads stdout, so it can pull from a password manager or a cloud secret store.

ansible-vault view --vault-id prod@~/.vault_prod group_vars/prod/vault.yml | grep -i api

Search inside a vault without decrypting to disk.

# group_vars/prod/vars.yml   (plain, greppable)
db_password: "{{ vault_db_password }}"

# group_vars/prod/vault.yml  (encrypted)
vault_db_password: hunter2

The indirection pattern: real names in plain text, values in the vault, prefixed vault_. Add no_log: true to any task that touches them.

06 · Galaxy & collections

Dependencies, pinned and reproducible.

ansible-galaxy collection install community.general
ansible-galaxy collection install 'community.general:>=8.0.0,<9'
ansible-galaxy collection install community.general --upgrade

Install, pin or bump a collection. Namespaced modules like community.general.ufw come from these.

# requirements.yml
collections:
  - name: community.general
    version: ">=8.0.0,<9.0.0"
  - name: https://github.com/org/private-collection.git
    type: git
    version: main
roles:
  - name: geerlingguy.docker
    version: 7.1.0

One file for both. Install it with:

ansible-galaxy install -r requirements.yml
ansible-galaxy collection install -r requirements.yml --force
ansible-galaxy collection list
ansible-galaxy collection list community.general
ansible-galaxy role list

What's installed and where. Handy when a module "doesn't exist" on the CI runner.

ansible-galaxy role init roles/nginx
ansible-galaxy collection init myorg.tools

Scaffold the standard directory layout so you never argue about it.

ansible-galaxy collection install -p ./collections -r requirements.yml

Install into the project instead of ~/.ansible. Set collections_path = ./collections in ansible.cfg and commit the lock.

ansible-galaxy collection build
ansible-galaxy collection publish myorg-tools-1.0.0.tar.gz --api-key "$GALAXY_TOKEN"

Package and publish your own collection to Galaxy or a private Automation Hub.

07 · Docs, lint, config

Offline reference and the tooling around it.

ansible-doc ansible.builtin.copy
ansible-doc -s ansible.builtin.copy   # snippet you can paste
ansible-doc -l | grep -i docker

Full docs with examples, or a ready-to-fill task snippet. No internet needed.

ansible-doc -t lookup -l
ansible-doc -t filter ansible.builtin.regex_replace
ansible-doc -t connection ssh
ansible-doc -t callback -l

-t switches the plugin type: lookup, filter, test, inventory, connection, become, callback, strategy…

ansible-config dump --only-changed
ansible-config view
ansible-config list | less

See what's different from defaults and which file it came from. Kills the "which ansible.cfg is it reading" question.

ansible-config init --disabled -t all > ansible.cfg

Generate a fully commented ansible.cfg with every option present but disabled. Uncomment what you need.

ansible --version
ansible-galaxy collection list 2>/dev/null | head

Shows config file in use, python version, and collection paths. The first thing to paste into a bug report.

pipx install --include-deps ansible
pipx inject ansible ansible-lint
pipx upgrade-all

Clean install away from system Python. pipx inject adds tools into the same venv so they share collections.

ansible-lint site.yml
ansible-lint --fix
ansible-lint --profile production

Catches non-FQCN modules, missing names, risky shell use, and more. --fix auto-rewrites the safe ones.

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/ansible/ansible-lint
    rev: v24.9.2
    hooks:
      - id: ansible-lint

Lint on every commit. Add --syntax-check in CI for the playbooks the linter doesn't own.

08 · Playbook patterns

YAML that reads well in six months.

- name: Deploy with rollback
  block:
    - ansible.builtin.git:
        repo: "{{ app_repo }}"
        dest: /srv/app
        version: "{{ app_version }}"
      notify: restart app
    - ansible.builtin.command: /srv/app/bin/migrate
      changed_when: "'applied' in migrate.stdout"
      register: migrate
  rescue:
    - ansible.builtin.command: /srv/app/bin/rollback
    - ansible.builtin.fail:
        msg: "Deploy failed on {{ inventory_hostname }}, rolled back"
  always:
    - ansible.builtin.file:
        path: /srv/app/.deploying
        state: absent

block / rescue / always is try / except / finally. A host that hits rescue shows as rescued and keeps going.

- name: Create users
  ansible.builtin.user:
    name: "{{ item.name }}"
    groups: "{{ item.groups | default(omit) }}"
    shell: "{{ item.shell | default('/bin/bash') }}"
  loop: "{{ users }}"
  loop_control:
    label: "{{ item.name }}"     # hides the whole dict from output
    pause: 1
    index_var: idx

default(omit) leaves the argument out entirely when the key is missing, so the module keeps its own default. label keeps the log readable.

- name: Wait for the API
  ansible.builtin.uri:
    url: "http://{{ inventory_hostname }}:8080/health"
    status_code: 200
  register: health
  until: health.status == 200
  retries: 30
  delay: 5

Poll until success. until uses the registered result; retries × delay is your timeout.

- hosts: web
  serial: [1, "25%", "100%"]      # canary, then a quarter, then the rest
  max_fail_percentage: 10
  any_errors_fatal: true
  pre_tasks:
    - ansible.builtin.command: /usr/local/bin/lb-drain {{ inventory_hostname }}
      delegate_to: "{{ lb_host }}"
  roles:
    - app
  post_tasks:
    - ansible.builtin.command: /usr/local/bin/lb-enable {{ inventory_hostname }}
      delegate_to: "{{ lb_host }}"

Rolling deploy. serial batches hosts, delegate_to runs the drain on the load balancer while iterating over the web hosts.

handlers:
  - name: restart app
    ansible.builtin.systemd:
      name: app
      state: restarted
    listen: "app config changed"

tasks:
  - ansible.builtin.template: {src: app.conf.j2, dest: /etc/app.conf}
    notify: "app config changed"
  - ansible.builtin.meta: flush_handlers   # run handlers NOW, not at play end

Handlers run once at the end of the play no matter how many tasks notified them. listen lets several handlers share one topic name. flush_handlers forces them early.

- ansible.builtin.command: generate-token
  run_once: true
  delegate_to: localhost
  register: token

- ansible.builtin.debug:
    msg: "{{ token.stdout }}"   # available on every host

run_once executes on the first host but the registered value is copied to all of them.

- ansible.builtin.set_fact:
    app_port: 8080
    cacheable: true

- ansible.builtin.include_tasks: "{{ ansible_os_family }}.yml"

- ansible.builtin.import_tasks: common.yml
  tags: [always]

import_* is static (parsed up front, tags apply to children). include_* is dynamic (loops and per-host paths work, tags don't inherit).

- name: Long compile
  ansible.builtin.command: make -j8
  async: 3600      # max seconds to run
  poll: 0          # fire and forget
  register: build

- ansible.builtin.async_status:
    jid: "{{ build.ansible_job_id }}"
  register: job
  until: job.finished
  retries: 120
  delay: 30

Run long tasks in the background and check on them later, so one slow host doesn't block the play.

- ansible.builtin.shell: |
    set -o pipefail
    curl -fsSL https://example.com/x.sh | sh
  args:
    executable: /bin/bash
    creates: /usr/local/bin/x

creates / removes make shell and command idempotent. pipefail stops a silent failure in the first half of a pipe.

- ansible.builtin.uri:
    url: https://api.example.com/deploy
    headers:
      Authorization: "Bearer {{ api_token }}"
  no_log: true
  environment:
    HTTPS_PROXY: "{{ proxy_url | default('') }}"

no_log hides the task's arguments and result from output and logs. Set environment per task, play or in group_vars.

- hosts: all
  gather_facts: false
  tasks:
    - ansible.builtin.wait_for_connection:
        timeout: 300
    - ansible.builtin.setup:

For freshly created machines: wait for SSH before facts, then gather explicitly.

- ansible.builtin.template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    validate: nginx -t -c %s
    backup: true

validate runs the check against the temp file first. A broken template never lands on disk. Works with visudo -cf %s, sshd -t -f %s, named-checkconf %s.

- name: Only when actually in --check
  ansible.builtin.debug:
    msg: "dry run"
  when: ansible_check_mode

- name: Still run during --check
  ansible.builtin.command: cat /etc/version
  check_mode: false
  changed_when: false

Make --check useful for plays that need real data mid-run.

- ansible.builtin.copy:
    src: files/
    dest: /etc/app/
  when:
    - app_enabled | bool
    - ansible_facts.os_family == "Debian"
    - "'web' in group_names"

A list under when is ANDed and reads better than one long line. Quote conditions that start with a string.

09 · Speed

Runs that take minutes, not lunch breaks.

[defaults]
forks = 50                    # default is 5
gathering = smart
fact_caching = jsonfile
fact_caching_connection = ~/.ansible/facts
fact_caching_timeout = 86400

[ssh_connection]
pipelining = True             # one SSH round-trip per task instead of three
ssh_args = -o ControlMaster=auto -o ControlPersist=10m -o PreferredAuthentications=publickey

The four settings that fix most "Ansible is slow" complaints. Pipelining needs requiretty off in sudoers, which it is on modern distros.

- hosts: all
  gather_facts: false      # or:
  gather_subset:
    - "!all"
    - "!min"
    - network

Fact gathering is often the slowest task in the play. Turn it off when you don't use facts, or subset it.

- hosts: all
  strategy: free

Each host races ahead independently instead of waiting for the slowest host at every task. Ideal for package installs, bad for anything that coordinates hosts.

- ansible.builtin.apt:
    name: "{{ packages }}"      # one transaction
    state: present

# not:
- ansible.builtin.apt:
    name: "{{ item }}"
  loop: "{{ packages }}"       # N transactions

Package, file, user and most modules accept lists. Looping over them is slower and noisier.

- ansible.builtin.command: expensive-thing
  throttle: 2

Limit concurrency for one task only (a shared API, a license server) while the rest of the play keeps full forks.

- ansible.builtin.synchronize:
    src: build/
    dest: /srv/app/
    delete: true
    rsync_opts: ["--exclude=.git"]

For directories with many files, synchronize (rsync) is orders of magnitude faster than copy.

ANSIBLE_CALLBACKS_ENABLED=profile_tasks,profile_roles,timer \
ansible-playbook site.yml

Measure before tuning. The summary at the end names the slowest tasks and roles.

ansible-playbook site.yml -e 'ansible_ssh_pipelining=true'

Try pipelining for one run without editing config. If nothing breaks, make it permanent.

Build lists of other hosts' variables. The extract trick is how you render every peer's IP into a config file.

{{ lookup('file', 'id_rsa.pub') }}
{{ lookup('env', 'API_TOKEN') }}
{{ lookup('password', '/dev/null length=24 chars=ascii_letters,digits') }}
{{ lookup('template', 'snippet.j2') }}
{{ lookup('pipe', 'git rev-parse --short HEAD') }}
{{ query('fileglob', 'files/*.conf') }}

Lookups run on the controller, never the target. query() always returns a list; lookup() joins with commas.

{{ ansible_facts['default_ipv4']['address'] }}
{{ ansible_facts['memtotal_mb'] }}
{{ ansible_facts['processor_vcpus'] }}
{{ ansible_facts['os_family'] }}      # Debian / RedHat / …
{{ inventory_hostname }}              # name in inventory
{{ ansible_facts['hostname'] }}       # name the host reports
{{ group_names }}                     # groups this host is in
{{ play_hosts }}                      # hosts in the current play

The facts you'll use most. Prefer ansible_facts['x'] over ansible_x; the latter is the legacy injected form.

    server {{ hostvars[host]['ansible_host'] }}:{{ app_port }} weight={{ hostvars[host].weight | default(1) }};
{% endfor %}
}
{% if tls_enabled | bool %}
    listen 443 ssl;
{% else %}
